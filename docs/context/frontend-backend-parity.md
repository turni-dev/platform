# Frontend/backend feature-parity — аудит 22.08.2026

> Снимок разрыва между тем, что уже умеет бэкенд, и тем, что реально можно сделать через `apps/web` (кабинет владельца) и `apps/core-site` (публичный сайт). Повод: владелец отметил, что бэкенд последние недели уехал вперёд (VK/Google/McpPort/capability-automation/policy-слои), фронтенд не подхватывает. Правило на будущее — в `AGENTS.md` §Delivery Loop п.5: бэкенд-карточка без экрана, который её использует, не считается закрытой.

## 1. `apps/web` (кабинет владельца) — по каждому HTTP-эндпоинту бэкенда

| Бэкенд API | Модуль | Экран в `apps/web` | Статус |
|---|---|---|---|
| `POST/GET /api/v1/auth/*` | tenancy (owner-auth) | `(auth)/login`, `/register`, `/verify` | ✅ покрыт |
| `GET/PUT /api/v1/agent`, `/agent/instructions`, `/agent/knowledge` | agent-core | `(cabinet)/agent`, `/agent/knowledge` | ✅ покрыт |
| `GET/PUT /api/v1/agent/automations` (allowlist пресетов) | agent-core | `(cabinet)/agent/automations` | ⚠️ покрыт частично — страница написана до того, как приземлились Google/VK-карты; текст буквально гласит «каталог появится, когда эти карты приземлятся» (`apps/web/src/app/(cabinet)/agent/automations/page.tsx`), хотя каталог пресетов уже не пуст |
| `GET/POST /api/v1/integrations/google`, `/consent`, `/callback`, `/resources` | integrations/google (McpPort) | — | ❌ **нет экрана**. Владелец не может подключить/увидеть/отозвать Google Calendar/Sheets из кабинета вообще |
| `GET/POST/PUT /api/v1/channels`, `/channels/vk` | channels | — | ❌ **нет экрана**. VK-подключение (проверка community key, статус) доступно только прямым вызовом API |
| `GET /api/v1/automations/pending`, `POST /:id/approve`, `POST /:id/reject` | automation (capability registry, смёржено 22.08) | — | ❌ **нет экрана**. Approval-флоу, который является ядром продукта (owner approval перед внешней записью), физически нельзя пройти из кабинета — только curl/Postman |
| Дашборд (счётчики/статус/таймлайн) — данных для него на бэкенде частично нет (нет endpoint-агрегатора) | — | `(cabinet)/dashboard` | ⚠️ страница — пустая заглушка (`page.tsx:27-30`, буквально «здесь пока пусто»); нет backend-эндпоинта, который бы отдавал сводку (pending-approvals count, статусы подключений) — это тоже дыра, не только фронтенд |
| policy (risk-слои, verdict) | policy | — | — нет отдельного API для чтения политики и не спроектирован экран; не блокер для MVP, но владелец не видит, почему агент отказал/спросил — see `design-ux.md` `ExplainWhy` |
| skills (registry) | skills | — | сознательно не в скоупе — сам skill execution ещё не подключён (см. task-board, карточка «Клиентский слой для MCP и скиллов») |
| observability (`agent.tool_call.recorded` через event bus) | observability/reporting | — | нет потребителя вообще (ни бэкенд-агрегатора, ни экрана) — сырьё для будущего дашборда/трейс-майнинга есть, витрины нет |

**Итог по `apps/web`:** 3 из 7 продуктовых бэкенд-поверхностей не имеют экрана вообще (Google-подключение, VK-подключение, approval-инбокс), ещё 2 требуют доработки (automations — актуализация текста, dashboard — превратить в реальную сводку, для чего нужен ещё и агрегирующий backend-эндпоинт). Это и есть тот разрыв, который назвал владелец.

## 2. `apps/core-site` (публичный сайт) — по бэклогу, не по API (сайт не ходит в продуктовый бэкенд напрямую)

Разрыв здесь другой природы: не «бэкенд обогнал», а «фичи из дизайн-спеки и бэклога полностью не начаты» — сам бэкенд для части из них (feedback/credits) тоже не существует, это CMS+backend-модератор фича целиком в бэклоге.

| Фича | В `design-ux.md` / task-board | В коде (`apps/cms/src/api/`, `apps/core-site/src/blocks`) | Статус |
|---|---|---|---|
| Каталог интеграций `/integrations` | §1, content-type `integration` | `apps/cms/src/api/integration`, `blocks/integration-catalog` | ✅ готово (закрыто 20.08) |
| **Единый маркетплейс** (integration+skill+profile, единый catalogue) | task-board Бэклог, «Единый маркетплейс интеграций, скиллов и профилей» | — | ❌ **не начато**. CMS содержит только старый content-type `integration`; `skill`/`profile` как типы каталога не существуют нигде — ни в CMS, ни как отдельный backend-каталог. Это ровно то, что имел в виду владелец под «тот же маркетплейс» |
| SEO-страницы маркетплейса (`/marketplace/:slug` canonical) | task-board Бэклог | — | ❌ не начато, зависит от пункта выше |

| Кредиты за вклад | §1.3, task-board | — | ❌ не начато (зависит от feedback) |
| Интерфейс модератора (обращения, начисление кредитов) | task-board | — | ❌ не начато |
| `/use-cases/*` страницы по сценариям | task-board | — | ❌ не начато (осознанно отложено «до первых живых интеграций») |
| L2 (бриф), L3 («Спасибо») | task-board, design-ux §2 | — | ❌ не сделано (L4 юр-страницы готовы) |
| Правовые страницы (`/legal/*`) | — | `blocks/legal-document`, 4 seed-страницы | ✅ готово (закрыто 22.08) |
| Разделы доверия `/about`, `/contact`, `/changelog` | task-board | — | ❌ не начато |

**Итог по `apps/core-site`:** маркетплейс (интеграции+скиллы+профили единым каталогом) — самая заметная дыра, которую отметил владелец; она не про рассинхрон с бэкендом (для неё и бэкенда пока нет — профили/скиллы существуют только как backend-контракты без публичного каталога), а про непочатый пласт бэклога.
