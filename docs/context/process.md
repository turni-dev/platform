# Процесс

## Роли и компетенции (кто что закрывает)

Новых людей нанимать не нужно — все компетенции закрыты существующей part-time командой + ИИ-ассистентом; главный дефицит — время фаундера (Максима), который совмещает продакта, системного аналитика, бэкенд и проджекта.

| Компетенция | Кто закрывает |
|---|---|
| Продакт | Фаундер + ИИ-ассистент |
| Бизнес-аналитик (user stories, критерии приёмки) | ИИ-ассистент генерирует → фаундер утверждает |
| Системный аналитик (модель данных, API-контракты, интеграции) | Фаундер (фулстек) + ИИ — критичная роль, не делегируется |
| Проджект | Фаундер, минимальный процесс: недельный спринт + демо в воскресенье + доска |
| UX/UI-дизайнер | Отдельный дизайнер |
| Фронтенд | Фронт/фулстек-кандидат |
| Бэкенд / AI-инженер | Фаундер — ядро не делегируется на старте |
| QA + LLM-evals | Частично ИИ + фаундер (особая компетенция: тестирование недетерминированной системы, eval-набор с первого дня) |
| DevOps | Джун-девопс по чек-листу, посильно с наставничеством |
| Юрист | Разово, закупка услуги (не входит в команду) |

### Артефакты для передачи в разработку (готовить до первой строки кода)
PRD/ТЗ на MVP (user stories + критерии приёмки) · UX-флоу (онбординг, approval-инбокс, недельный отчёт) · модель данных (тенант, агент, диалог, сообщение, действие, политика, approval, отчёт) · контракт policy-слоя (typed schema) · eval-датасет v0 (50 реальных диалогов, разметка типовое/рисковое) · Definition of Done · доска задач.

Минимальный процесс для part-time команды: недельный спринт (планирование пн 30 мин асинхронно → демо вс 30 мин созвон), доска с тремя колонками, задача не входит в спринт без критериев приёмки, ИИ-ассистент ведёт протоколы и черновики ТЗ.

## Поставка по отделам (MVP-1)

| Отдел | Работы | Критерий готовности |
|---|---|---|
| DevOps (джун + менторинг 30 мин/день) | CI/CD с eval-гейтом, staging+prod, секреты, бэкапы, мониторинг | Коммит в main едет на staging сам; алерт p95>10с работает |
| Разработка (фаундер, потом фронт) | Ядро, policy engine, сценарии, онбординг, инбокс, отчёт, события | Eval FN≤2%, p95≤10с, обход policy падает тестом |
| Дизайн (параллельно ядру) | UI-кит, прототип, 5 юзер-тестов, хендофф | ≥4/5 проходят флоу; UI-код только после |
| QA (минимум, фаундер) | Чек-лист пилота, разметка eval | 0 блокеров, ≤3 minor |
| Контент | Тексты бота, FAQ, гайд владельцу | Владелец понял без созвона |
| Запуск | Пилот из кастдев-воронки, неделя жизни, отчёт | Go/no-go на MVP-2 |

Зависимости: кастдев → ядро (критический путь, фаундер) ← DevOps-скелет+CI; дизайн → юзер-тесты → UI-код фронтом (после ядра); ядро+UI → QA → пилот 7 дней ← контент. Разгрузка фаундера: фронт-дев берёт инбокс и отчёт по API-контракту.

### Майлстоуны (по готовности, без дат)
M1 Скелет (деплой main→staging, eval-гейт живой, секреты не в коде) → M2 Policy-ядро (1 сценарий e2e, обход policy невозможен — **после M2 скоуп-фриз**) → M3 Прототип (5 юзер-тестов, ≥4/5, правок ≤10) → M4 Полнота (6 сценариев + онбординг + инбокс + отчёт на staging; FN≤2%; p95≤10с) → M5 Пилот-готовность (QA подписан, гайд готов) → M6 Пилот жив (7 дней без severity-1, ≥20 реальных диалогов, go/no-go).

### Definition of Done
- **Задача:** PR в main · тесты зелёные · eval-гейт · события аналитики · ничего мимо policy · закрыта с комментарием.
- **Эпик:** + демо-видео ≤3 мин · p95 в норме · доки обновлены · принят фаундером.
- **Этап:** + майлстоуны приняты · отчёт пилота · ретро · бэклог следующего готов.

### Ритуалы и канбан (part-time, доли)
Канбан + недельная каденция (спринты с обязательствами не работают при плавающей ёмкости). Доска: Backlog → Ready → In Progress → Review → Done. **WIP = 1 задача на человека.**

Ритуалы (асинхронно, Telegram): чекин вт+пт (✅ сделал / ▶️ дальше / 🚧 блокер / ⏱ часов до demo) · блокер — сразу отдельным сообщением · **demo-day каждое воскресенье до 20:00** (видео/скрин; нет результата — «пустая неделя, причина») · живой созвон 45 мин раз в месяц · ретро раз в месяц.

Защита фаундера: один «офисный час»/нед на Review и вопросы; всё в топик «для фаундера», не в личку; принимает только код ядра.

**Анти-затухание:** публичное обязательство при взятии задачи · «красная неделя» (пропал чекин+demo → задача авто-в-Ready + проверка) · две красных подряд → пауза вестинга · вестинг за вклад: активный месяц = ≥2 принятых задачи.

**Здоровье процесса:** lead time ≤14 дн · 0 задач без движения 7+ дн · Review ≤3 дн · demo-покрытие ≥4/5 · поток ≥3 задач/нед.

**Эскалация фаундеру немедленно:** действие мимо policy · красный eval в main · инцидент пилота · «выпадаю на неделю+» · утечка данных.

### Практики работы с ИИ-агентами над кодом (внешняя практика, зафиксирована к сверке с процессом)
1. Строго ограничивать области кода для агента — совпадает с nx module boundaries, CODEOWNERS на contracts/миграции, PR ≤400 строк, ветка ≤2 дня.
2. Сокращать время eval-прогона — держать eval-раннер быстрым, не тормозить цикл.
3. Подкладывать агенту MD-файл с ресёрчем на старте — у нас это `AGENTS.md` + профильные заметки-спеки.
4. Экономика: подписка ClaudeCode Max выгоднее оплаты по токенам API (до 40 раз) — проверять актуальность условий.
5. Основной результат агента достигается за <1000 итераций.
6. Следить за дисперсией оценки (eval variance) — добавлено как отдельный health-показатель eval-гейта (наряду с FN≤2%).

## Репозиторий: нейминг и kickoff

### Нейминг
- GitHub-организация: `turni`.
- Монорепо (Nx, один репозиторий): `turni` → `github.com/turni/turni` (запасные варианты: `platform`/`turni-app`).
- npm-scope: `@turni/*` (`@turni/contracts`, `@turni/db`, `@turni/ui`, `@turni/domain-*`).
- apps: `api`, `web`, `worker`, `landing`, `cms`; packages: `widget`.
- Соглашения: lowercase, kebab-case, английский в коде/путях/БД; UI-текст — русский. Инфра — в `tools/` и `deploy/`.
- Запасные имена организации: `turni-ai`, `getturni`, `turni-hq`.

### Kickoff-задача для скаффолда (спринт С1)
Единственный источник правды — заметки в Obsidian (папка «1. Projects/Личное/ИИ сотрудник или команда»); при расхождении кода и заметок заметки главнее.

Скаффолд включает: Nx-монорепо (pnpm) с apps `api/web/worker`, libs `contracts/db/domain/*/shared/ui`, `packages/widget`, `tools/bootstrap`, `deploy/`, `docs/adr`; NestJS (Fastify) модульный монолит в `api`, `worker` — тот же код с BullMQ entrypoint; домены общаются только через `@turni/contracts`; strict TS + eslint (no-any, no-floating-promises) + coverage-гейт ≥80% на domain/policy; Drizzle + PostgreSQL схема v1 (~20 таблиц, id UUIDv7) с FORCE RLS, хелпер `withTenant` (SET LOCAL), автотест RLS-изоляции; `libs/contracts` — Zod-DTO + интерфейсы портов + Fake-адаптеры; docker-compose local (Postgres+pgvector, Redis, MinIO) + CI (build/test/migrations) с авто-деплоем main→staging (GHCR) + CODEOWNERS на contracts/миграции; hello-world `/healthz`.

### AGENTS.md — железные правила (нарушение = красный ревью)
1. Ничего мимо PolicyEngine (default-deny). Аллергены/деньги/жалобы → всегда approval (locked-политики, read-only).
2. Vendor-тип не пересекает границу порта — только Zod-DTO. Внешние сервисы только за портами, у каждого есть Fake.
3. Мультитенантность: всё через `withTenant` (SET LOCAL app.tenant_id), FORCE RLS, роль `app_rw NOBYPASSRLS`. «Голый» db в worker запрещён.
4. Strict TS, `any` запрещён, no-floating-promises. Zod на каждой границе (HTTP/WS/очереди/env/LLM-вывод). Единственный источник типов — `@turni/contracts`.
5. Промпты в БД, immutable-версии; `active=true` ставит только CI после зелёного eval. Eval-гейт FN≤2% — блокирующий.
6. PII: redaction перед LLM (fail-closed) + hash+encrypt+mask; тела сообщений не в логи. RU-first/Yandex-first LLM; second provider выключен в MVP; **OpenRouter не используется**.
7. Idempotency на мутирующих POST и вебхуках (Postgres). Undo 30с. FSM-статусы = text+CHECK (не enum). id = UUIDv7.
8. Миграции expand/contract; `CREATE INDEX CONCURRENTLY` вне транзакции. Секреты только `sops/age`.
9. Гостю не стримим ответ (policy видит ответ целиком). p95 ≤10с. Агент всегда раскрывает, что он ИИ.
10. OWASP Top 10:2025 + OWASP LLM Top 10 — обязательный минимум.

### Как работать над задачей
1. Взять задачу из доски (лейн «Готово к работе», WIP=1), прочитать связанную спеку.
2. Mini-спека (цель/вход/выход/критерии/ловушки) первым комментарием.
3. Trunk-based: ветка ≤2 дня, PR ≤400 строк, фичефлаги.
4. DoD: PR в main · тесты+eval-гейт зелёные · события аналитики · ничего мимо policy · ADR/доки обновлены.
5. CODEOWNERS (libs/contracts, миграции) — без ревью фаундера не менять.

### Стек (справочно)
TypeScript strict · Nx-монорепо · NestJS (Fastify) модульный монолит · Drizzle · PostgreSQL (self-host) + pgvector(768, HNSW cosine) + citext · Redis + BullMQ · XState (FSM) · Next.js + shadcn (Tailwind только в libs/ui) + SCSS · RU-first LLM за `LlmPort`/`EmbeddingPort` (YandexGPT + Yandex Text Embeddings primary) · Docker Compose (без k8s) · GHCR.
