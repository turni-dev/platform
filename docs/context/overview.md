# Обзор продукта: платформа ИИ-сотрудников

> Актуальное состояние продукта и видения. Детальный реестр решений — `decisions.md`, scope/этапы — `product-scope.md`, гейты кодинга — `coding-readiness.md`.

## Что это

Универсальная платформа ИИ-сотрудников: агент настраивается под человека и его бизнес через помощника-онбординг, подключается к инструментам (MCP-реестр), умнеет со временем через память и работает под контролем (approval + аудит).

Продаём чувство: «У тебя есть сотрудник, которому можно доверять» — успеваешь больше лично и в бизнесе. Продаём через шаблоны ролей поверх одного ядра (первый — «ИИ-администратор» для общепита, сейчас — вторичный сценарий, см. ниже).

Почему мы: сочетание контроля + прозрачности + растущей памяти в SMB-цене не делает никто (проверено теардаунами Suvvy/Wikibot).

**Важно (курс на 16.08.2026, разворот):** от общепита как входной вертикали отказались. Основной вход теперь — **персональные автоматизации владельца/специалиста** (личный агент: почта, календарь, таблицы, заметки, мессенджер), продаваемые через агентский трек и корп-сайт. Общепитовый материал (6 сценариев, policy-матрица, eval-датасет) сохраняется как вторичный шаблон и тестовый набор, но не определяет продуктовый scope MVP-1.

## Каноническая модель агента (ядро всего)

**Агент = Role + Instructions + Knowledge Sources + Memory + Tools + Workflows + Permissions + Approval Rules + Runtime Backend + Audit Logs + Execution Environment.** Не промпт — сущность, которая настраивается, ограничивается, наблюдается и совершенствуется со временем (память пополняется из разговоров и решений владельца).

| Элемент агента | Реализация |
|---|---|
| Role + Instructions | `identity.md` + `policies/*.md` (правила естественным языком) |
| Knowledge Sources | `knowledge/` + импорт файлов/таблиц; дальше — сайт, Git (Obsidian) |
| Memory | memory_files с ревизиями; `learned/` — только через подтверждение владельца |
| Tools | Tool Registry за `McpPort`: MCP — предпочтительный транспорт, API fallback — только versioned skill adapter |
| Workflows | Сценарии + автоправила из approvals + триггеры (Reporter) |
| Permissions | Policy Engine, default deny |
| Approval Rules | ApprovalService: risk-классы, SLA, ✅/✏️/❌ |
| Runtime Backend | Yandex-first за `LlmPort`/`EmbeddingPort`: YandexGPT + Yandex Text Embeddings primary; второй провайдер опционален позже; retry/degradation in-app (`model_configs`), конфиг per-agent |
| Audit Logs | events + таймлайн «что сделал и почему + источник» |

Таблица `agents` заложена с первого дня (MVP: один агент на клиента; мастер-роутер — passthrough-интерфейс под будущие команды агентов).

## Оси масштабирования

Правило: **ядро одно, расширение = новый элемент на оси, не переписывание.**

1. **Шаблоны ролей** — администратор общепита → куратор школы · админ глэмпинга · личный ассистент · команда разработки. Шаблон = пресет (роль + знания-скелет + сценарии + политики + каналы + инструменты). Новая вертикаль ≈ неделя на шаблон, не новый продукт.
2. **Каналы** — веб → TG → VK → MAX → Avito → email → голос.
3. **Инструменты / реестр навыков** — брони → Sheets → iiko → календарь → Todoist → Obsidian-Git → любой MCP-сервер.
4. **Глубина автономности** — стажёр → помощник → администратор → команда агентов.

### Профили, скиллы и MCP-каталог (решение 20.08)

**Профиль агента** — immutable versioned composition: Role, Instructions, knowledge skeleton, skills, MCP-интеграции, workflows, permissions, approval rules. Применение профиля создаёт tenant-scoped конфигурацию; монотонный резолвер не даёт профилю ослабить locked policy или расширить capabilities.

**`McpPort` — единственная граница capability.** MCP — предпочтительный транспорт. Если у сервиса нет MCP — узкий versioned skill adapter с тем же policy/approval/audit/Fake-контуром. Google Calendar/Sheets — первый first-party provider.

**Маркетплейс** — один реестр интеграций (включая MCP providers), скиллов и профилей; каждый элемент имеет canonical SEO-страницу. Community-публикация, revenue share — после релиза, после vetting/sandbox и юридической/налоговой/antifraud модели. Полная карта — `marketplace-mcp.md`.

## Позиционирование: два уровня

- **Бренд — продаём чувство:** «У тебя есть сотрудник, которому можно доверять». Простой в подключении, безопасный с данными, умнеет со временем.
- **Продажа — продаём результат в нише:** конкретный шаблон/оффер/демо (пример: администратор для кафе).

Почему не «универсальный инструмент» в лоб: рынок завален «универсальными конструкторами» (Suvvy, Wikibot), 54% не видят ценности в универсальности. Универсальность — внутреннее свойство и moat; ниша — дверь, через которую платформу покупают.

## B2C-трек

Личный агент (календарь, туду, Obsidian через Git, почта) — тот же агент, другой шаблон. Фаундер — пользователь №1, дог-фуд ядра на себе с первого дня; в продажу — после B2B-валидации.

## Agent vs Workflow — две композируемые примитивы

Правило выбора (по цене ошибки и сложности):

| Вопрос | → |
|---|---|
| Цена ошибки высокая (аллергены, деньги, жалобы)? | **human-in-the-loop = approval**, независимо от прочего |
| Простая/рутинная/дешёвая (FAQ, напоминание, отчёт)? | **Workflow** |
| Сложная + ценная + выполнимая + ошибка дешёвая? | **Agent** |
| Не все части выполнимы (нет модели столов)? | **Reduce scope** → «заявка», не «подтверждение» |

- **Workflow** (детерминированный путь): FAQ-exact, напоминания/перенос, сбор отзыва, недельный отчёт, opt-out.
- **Agent**: разговорная бронь-заявка, нюансный FAQ, «где курьер».
- **Agent + approval**: аллергены без точного совпадения, банкет/деньги, жалоба/компенсация, кампании, отзыв на картах.

Workflow — внутренний примитив, владельцу виден как «правила/автоматизации»; НЕ визуальный конструктор в MVP.

## Execution Environment — граница безопасности и мультитенантности

Изолированный per-tenant контекст, в котором исполняются агент, инструменты, скиллы и workflows: tenant context (RLS `app.tenant_id`), secrets & credentials (`credentials_enc` + sops/age), sandbox/изоляция исполнения (allowlist + deny-побеждает + sandbox рисковых), env/config/feature flags, budgets & limits (iteration budget, cost-учёт, circuit-breaker), capabilities context (Tool Registry allowlist, default-deny), network/egress (SSRF-guard), workspace (memory/knowledge per tenant), runtime backend (LlmResolver Yandex-first).

Принцип: инструмент/скилл/workflow никогда не исполняется вне явно заданной среды — «голого» исполнения без среды нет.

## Самоулучшение и мульти-агентность (управляемо)

- **Самоулучшающиеся инструменты:** learned-pipeline (правки владельца → кандидат-правила) + ночной retro-eval. Железное правило: любое самоулучшение = предложение → одобрение (владелец/CI) → eval-гейт, никогда авто-применение в прод. Этап — Платформа, не MVP.
- **Trace-mining → синтез скиллов** (добавлено 16.08): агент/ночная задача читает трейсы вызовов инструментов, находит повторяющиеся цепочки, предлагает свернуть в скилл/воркфлоу. Контур: трейсы → детекция паттерна → черновик → предложение → одобрение → eval-гейт → версия активна → замер эффекта (не дал выигрыша — откат). Порог доверия к выборке — минимум наблюдений, не 3 случая. Безопасность: redaction перед майнингом (иначе prompt injection), синтезированный скилл не расширяет права. Этап — Платформа, но **инструментирование трейсов делается уже сейчас**.
- **Мульти-агентная система:** архитектура готова (Master Router = passthrough в MVP, таблица `agents` поддерживает много, per-agent Execution Environment). Первый шаг (P1): supervisory-агент — второй агент-«полицейский» проверяет риск-критичные ответы. Дальше (Платформа): специализированные под-агенты под мастер-оркестратором; под-агенты read-only, действия — через approval родителя/policy.

## Боевой кейс (Вера Круч) — что вшито в ядро

Первый ИИ-сотрудник на живом клиенте: Hermes (встроенный Google Workspace skill `$GAPI` + Telegram-gateway), навык `project-docs-telegram`. Задача — вести проектные/личные таблицы в Google и слать апдейты в Telegram. После первого провала клиент засомневался («пока всё не очень»), предлагал оплатить 50% — доверие восстановили доработкой. Продуктовый сигнал: **первое впечатление от ИИ-сотрудника решает.**

**Ключевые провалы → причины → решения (хронология):**
1. Документы созданы «чохом», без таблицы — агент пошёл в Google Docs текстом → правило: таблицы только в Sheets, запрет текстового дампа.
2. «Завис» на фото-образце 3 мин — не было ветки «распознать фото → собрать таблицу» → явная ветка фото в навыке.
3. Плодит файлы/версии вместо правки — анти-паттерн ИИ (новый файл на каждое обновление) → правило «один документ, найти по имени → id → правка на месте».
4. Стоимость 80 000 ₽ попала в общий лист — агент копировал шаблон с колонкой «Стоимость» → правило «стоимость никогда в общий лист/группу» + `audience:"group"` автоматически убирает колонку.
5. Сумма утекала бы даже из свободного текста — скрабинг был только в Telegram, не в ячейках → добавлен scrub денег из текстовых ячеек для `group`.
6. «Command Approval Required / Confusable Unicode», спам одинаковыми блоками — агент генерил сырой inline-python с кириллицей мимо скрипта → правило: данные через `data.json` + скрипт, короткий ASCII-вызов.
7. Риск самовольной отправки в рабочую группу — не было гейта подтверждения → владельцу сразу, в группу — только после явного «да».
8. Знает правило (процитировал), но всё равно нарушил — навык читается, но не исполняется → правило-маршрутизатор в постоянные инструкции + узкий путь через скрипт.
9. Импровизация кодом, нестабильность — модель `gpt-5.4-mini` слабо держит многошаговый навык → апгрейд модели (`gpt-5.5`, для критичных задач — sonnet-4.6/opus-4.8).
10. Ранее — «зависания» на доступе к Google — параллельный remote MCP `google_drive` ловил повторный OAuth → remote MCP отключён, только встроенный `$GAPI` на токене.
11. После «правок» поведение не менялось — деплой файла ≠ перечитка навыка → редеплой `SKILL.md`+`scripts/` → `config check` → рестарт.
12. (внутреннее) раздутый/сбойный навык — `SKILL.md` был задвоен → переписан в один чистый файл.

**Правила, вшитые в навык:** (1) один документ, правим на месте, никаких авто-версий · (2) таблица = Google Sheets, не текстовый дамп в Docs · (3) стоимость никогда в общий лист и в группу · (4) без сырого inline-python с кириллицей — данные через файл и скрипт.

**Факторы вне текста навыка:** модель (mini-класс хуже держит длинные навыки) · инфраструктура (лишний канал доступа = OAuth-зависания, один проверенный путь надёжнее) · принуждение ≠ знание (нужны постоянные инструкции + сужение инструмента) · security-скан (homoglyph: кириллица в shell-командах триггерит защиту и ломает поток — данные через файлы, не в командной строке).

Подтвердило и дало острые правила-стандарты для платформы:

- **Детерминизм — в код, не в модель.** Всё критичное (конфиденциальность, формат, идемпотентность) — в скрипт/Policy Engine.
- **Approvals для необратимого и внешней рассылки.**
- **Правка на месте, не плодить версии** = идемпотентность (`UPDATE WHERE pending`).
- **Первое впечатление решает** → trial/«режим стажёра» + eval-гейт обязаны ловить грабли ДО клиента.

Острые правила-стандарты:
1. Дублируй негативные ограничения (defense-in-depth): фильтр в данных И self-check после действия.
2. «Знает» ≠ «делает» — принуждение через детерминированный путь + сужение инструмента (default-deny), не инструкция в промпте. Приёмочный тест — без ручных подсказок.
3. Структурированный I/O инструментов — данные через DTO/Zod, не сырой пользовательский текст в команде (кириллица в shell триггерит homoglyph-скан).
4. Модель уровня задачи — tier модели под сложность роли.
5. Один проверенный путь доступа — минимум каналов, каждый — веттинг.

**DoD навыка/сценария готов к клиенту:** критичное в коде · негативные ограничения продублированы · approval на необратимое/рассылку · правка на месте · модель уровня задачи · один путь доступа · правило-маршрутизатор в постоянных инструкциях · приёмочный тест без подсказок + крайние случаи · нет пользовательского текста в shell.

# Агентский трек (приватные агенты) — бизнес-процесс

> Второе предложение на домене turni, параллельно с SaaS. Начало: 12.07.2026.

## Идея

Мы вручную разворачиваем и настраиваем ИИ-агента **на серверах клиента** (client-hosted, single-tenant) — в отличие от SaaS (наши серверные агенты). Клиент платит за результат под ключ; то, что здесь делается руками, в SaaS со временем станет самонастройкой через онбординг.

Это concierge MVP / Wizard of Oz для платформы: ранние деньги + знакомство рынка + ручные кейсы как сырьё для автоматизации (каждый клиентский агент — прогон гипотезы «шаблона вертикали»). Не жертвуем скоростью ради вида автоматизации — каждая ручная настройка осознанно фиксируется как кандидат в будущий шаблон.

## Модель

| | Приватный агент | Серверные агенты (SaaS) |
|---|---|---|
| Хостинг | На сервере клиента, single-tenant | Наш прод, мультитенант |
| Переиспользуется из ядра | agent-engine: `LlmPort`, Policy Engine, Memory, Execution Environment/sandbox | Всё ядро включая RLS/`withTenant`, tenancy, биллинг |
| Продажа | Project-based, под ключ | Подписка |
| Обновления | Вручную по SSH, НЕ continuous deploy | GHCR → ssh → compose (CI/CD) |
| Кто делает | Максим / девопс | CI/CD |

## Воронка

1. Лендинг (главная turni.*) → оффер «соберём вам вашего агента».
2. Бриф (форма или созвон).
3. Скоуп — граница «под ключ / доп. работа» фиксируется до/сразу после брифа (не постфактум — риск расползания в бесплатный консалтинг).
4. Настройка — параллельно: инфраструктура (VPS клиента) + бизнес-сценарии (переиспользует O1-онбординг флоу SaaS, только проходит его Максим за клиента).
5. Сдача — приёмка по DoD навыка (см. выше, кейс Веры).
6. Поддержка — ручная, не непрерывная.

## Открытые вопросы агентского трека

1. Тайм-бокс — решено 12.07: пока нет, вернуться если трек начнёт теснить MVP-1.
2. Kill-criteria (нет оплаченного клиента за 4 недели → закрыть) — кандидат, не подтверждён.
3. Кто первый клиент — не решено.
4. Шаблон/чек-лист брифа — оформить до первого реального созвона.
5. Порог, с которого артефакт «Кейс — клиент» обязателен — не решено.

## Корп-сайт turni.ru (ревизия 16.08.2026)

Лендинг агентского оффера вырос во второй трек — корп-сайт. Структура (расширение реестра): Главная (hero → шаги → bento-принципы → стена интеграций → FAQ → CTA) · `/products/*` · `/integrations` (каталог интеграций и скиллов — закладывается сразу, это SEO-слой и доказательство живого продукта) · `/use-cases/*` (после первых интеграций) · `/cases/*` · `/feedback` (публичная система обратной связи) · `/blog/*` · `/changelog` · `/about`, `/contact` · `/legal/*`.

Принцип сборки: макеты — блоки, страницы собираются в CMS (Strapi) из блоков; каталог интеграций — единственное исключение, свой тип контента.

**Публичная система обратной связи:** обращение (баг/идея) с текстом, опциональным контактом, выбором «под именем/анонимно». Жизненный цикл: `новое → на модерации → опубликовано → в работе → сделано/отклонено (с причиной)`. Публикуется только прошедшее модерацию. Анонимность честная — контакт хранится приватно только для ответа. Голосование «+1» включено в первую версию (решение 16.08), с защитой от накрутки.

**Кредиты за вклад (решено 16.08):** полезное действие (баг/идея) даёт кредиты — внутреннюю валюту на использование продукта, ставки публикуются на странице продукта. Правила: платим за подтверждённое, не за отправленное · дубликат платит только первому · идея оплачивается по факту продвижения (максимум — за выпущенное) · месячный потолок эмиссии · право отклонить без выплаты · кредиты не выводятся в деньги и не передаются (это скидка на услугу, не выплата — юридическая формулировка и налоговая сторона к юристу обязательно) · кредиты — обязательство в учёте, а не бесплатный маркетинг · модерация — узкое место, при потоке выше возможностей — временно закрыть приём.

**Оффер (уточнение 16.08):** оффер переехал на `/products/private-agent`, корень — под будущую главную корп-сайта. Предмет услуги — не канал: собираем персональные автоматизации (облако/hermes-агент + MCP/скиллы); канал общения — выбор клиента, не суть услуги. Формат: бриф → формализация требований (согласуется до начала работ) → развёртывание в контуре клиента → поддержка. Согласие на зарубежное размещение данных — отдельный необязательный вопрос формы (не приписка к согласию ПДн). Заявка = запись на консультацию (слот опционален).

Визуальный курс — референсы AgentArea (нумерованные шаги, bento-сетка принципов, стена логотипов интеграций, честный футер Platform/Resources/Company/Legal), Notion (навигация Product/Solutions/Resources с описанием, use-case страницы под конкретный сценарий, раздел «что нового»), Todoist/Anthropic (спокойный минимализм, крупная типографика, воздух). Диагноз «дешёвого» вида: нет вертикального ритма (нужно 96–160px десктоп секции), типографика без контраста (заголовок кратно крупнее текста), пустые места вместо графики, одинаковые прямоугольники подряд вместо bento-сетки, нет доказательств (логотипы/скриншоты/цифры).
