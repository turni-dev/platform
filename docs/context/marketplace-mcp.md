# Маркетплейс, MCP и композиционные профили

> Решение 20.08.2026. Цель — один функционал агента подключается к N сервисам без переписывания агента; при этом расширение не обходит policy, approval, аудит и tenant-изоляцию.

## Канон

- **MCP — предпочтительный транспорт интеграции.** Агент и automation работают только с нашим `McpPort`: discovery, вызов и метаданные capability. Google Calendar/Sheets — первый first-party MCP-провайдер. Внутренняя реализация может использовать Google SDK, но SDK не пересекает границу провайдера.
- **Нет MCP — есть скилл-адаптер.** Скилл — версионируемая capability с Zod-входом/выходом, минимальными правами и Fake. Может вызвать MCP-capability или узко реализовать API fallback; отдельной ветки в агенте не появляется.
- **Профиль агента — композиция, а не копия агента.** Версионируемый профиль состоит из Role, Instructions, knowledge skeleton, skills, MCP-интеграций, workflows, permissions и approval rules. Применение профиля создаёт tenant-scoped конфигурацию агента; нижние слои могут только ужесточить политику.
- Все discovery и вызовы происходят только в Execution Environment: `tenant + secrets + sandbox + budget + capabilities`. `tool_discovery` также проходит PolicyEngine; внешняя запись остаётся approval-controlled и idempotent; в аудит уходят метаданные без тел сообщений, промптов и секретов.

## Маркетплейс

Один каталог с тремя типами элемента: **интеграция** (включая MCP-провайдер), **скилл**, **профиль**. У каждого — стабильный slug, описание, версия, автор/владелец, лицензия, статус публикации, совместимость и обязательная сводка запрашиваемых прав.

Каталог фильтрует все типы на одной странице, но у каждого элемента — отдельная canonical SSR-страница и запись в sitemap (SEO-вход по конкретному запросу). Билдер Strapi остаётся для информационных страниц, статей и use cases; страницы элементов маркетплейса рендерятся из структурированных записей каталога, не из произвольных блоков.

## Порядок и границы

1. **M1 Core:** `McpPort` + allowlist + first-party Google provider + Fake + существующий policy/approval/idempotency путь.
2. **Платформа:** композиционные профили и безопасное применение к tenant-агенту.
3. **Growth:** единый структурированный маркетплейс и отдельные SEO-страницы. Существующий каталог интеграций — стартовая миграция, не второй каталог.
4. **После релиза:** community-публикация только после moderation/vetting и sandbox для сторонних исполняемых возможностей; затем referrals, bonus attribution и revenue-share/payout — после юридической, налоговой и antifraud-модели.

## Не входит сейчас

Нет произвольного remote MCP, загрузки исполняемого кода, browser/exec, публичной публикации без модерации, балансов/выплат и визуального workflow-builder. Песочница из карточки «перед MCP-каталогом» обязательна до первого стороннего исполняемого инструмента.
