# Готовность к кодингу — гейты и чеклисты

> Сводка «что закрыто и что блокирует» по 4 направлениям. **Ключевой вывод:** кодинг ядра (E1→E2→E3→E4) разблокирован — оба настоящих блокера сняты (LLM-рантайм решён RU-first; eval-seed готов). Инфра и юр-минимум — гейты **пилота**, не кодинга. Можно кодить E1-скелет, не дожидаясь их.

## Открытые блокеры (осталось 2, оба вне кода)

Решено 10.07: LLM RU-first ✅ · eval-seed ✅ · инфра = self-host Postgres ✅ · эмбеддинги = vector(768) Yandex Text Embeddings v2 ✅. Кодинг ядра разблокирован.

### Блокер 1 — Юр-минимум (до пилота)
Владелец: Максим + юрист (разово).

- ИП — подать на регистрацию (УСН)
- Юрист — выбрать
- РКН-конструкция — уведомление оператора ПДн + проверка трансгранички (RU-first упростил)
- Оферта
- Политика конфиденциальности + cookie
- DPA (обработка ПДн, дисклеймер)
- Согласие ПДн в виджете + журнал согласий (152-ФЗ, в scope E6)
- ООО + вестинг (4 г / клифф 12 мес) — до старта команды

**Exit:** до приёма реальных гостевых ПДн — оферта/политика/cookie/DPA опубликованы, согласие в виджете работает, РКН провалидирован юристом.

### Блокер 2 — Дизайн → прототип (гейт UI-кода E6)
Владелец: дизайнер + продажник. Порядок жёсткий: прототип → 5 тестов ≥4/5 → хендофф → UI-код.

- Figma-прототип по build-ready спекам: онбординг 8 экранов + инбокс + отчёт
- Рекрут 5 владельцев на юзер-тесты
- 5 юзер-тестов, цель ≥4/5 успешных
- Итерация прототипа (если <4/5)
- Хендофф-спека компонентов (= DoD, a11y WCAG AA)

**Exit:** хендофф принят (≥4/5 на тестах + a11y AA) → разблокирует UI-код E6. Ядро (E1–E5, E7) кодится параллельно, не ждёт.

## Гейт E6 — дизайн → UI-код (на дизайнере)

Порядок: Figma-прототип (онбординг 8 экранов + инбокс + отчёт) → 5 юзер-тестов с владельцами (≥4/5 успешных, иначе итерация) → Хендофф-спека компонентов (a11y WCAG AA) → UI-код (стартует только после хендоффа).

Параллельность: ядро (E1–E5) и E7 кодятся параллельно с дизайном — UI-задачи E6 ждут только прототип.

### Verification SQL — pgvector + citext (до фриза схемы)
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS citext;
SELECT extname, extversion FROM pg_extension WHERE extname IN ('vector','citext');

-- проверить размерность под RU-модель эмбеддингов и доступность HNSW
CREATE TEMP TABLE _probe(id int, e vector(768));   -- РЕШЕНО: dim=768 (Yandex Text Embeddings v2; EmbeddingsGigaR=2560 не подходит без миграции)
CREATE INDEX ON _probe USING hnsw (e vector_cosine_ops);  -- если HNSW недоступен → ivfflat fallback
DROP TABLE _probe;
```
Self-host: ставим pgvector из исходников/пакета сами (`make install` или apt `postgresql-NN-pgvector`) — блокера доступности расширения нет. Цена self-host — бэкапы/PITR/HA на нас: WAL-archiving + PITR (pgBackRest/wal-g→S3) + ежедневный pg_dump→S3 + квартальный restore-drill.

## Гейт пилота — юр-минимум (на Максиме + юристе)

**Exit-критерий:** до приёма реальных гостевых ПДн на пилоте — оферта/политика/cookie/DPA опубликованы, согласие в виджете работает, РКН-вопрос провалидирован юристом.

## Что разблокировано прямо сейчас (можно коммитить)

1. **E1 скелет:** Nx+Nest+Drizzle+CI «hello world в проде» (local compose, Fake-адаптеры) — ничего внешнего не нужно.
2. **E2 пайплайн:** LlmResolver + FakeLlm → потом RU-адаптеры (нужны только ключи, не инфра).
3. **E3 память + E4 policy:** eval-seed готов → eval-раннер + CI-гейт пишутся сразу.
4. Порядок первой недели — без изменений («Первая неделя фаундера», Тех-решения консилиум).

**Единственные правки в план кодинга от Yandex-first:** (1) адаптеры `yandexgpt/yandex-embeddings` вместо `openrouter`; (2) embeddings: `vector(768)` под Yandex Text Embeddings v2; (3) eval-judge начинает с Yandex judge, second-family judge — только если eval-качество не проходит.
