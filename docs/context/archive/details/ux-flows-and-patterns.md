# UX: принципы, ключевые флоу, план валидации

Рабочий документ UX Researcher (12.06.2026) для дизайнера/прототипа.

**Принципы:** mobile-first (владелец с телефона между сменами, approve свайпом); язык кухни, а не IT-термины; прогрессивное раскрытие (решение + одна кнопка, детали за тапом); доверие через предсказуемость (агент показывает намерение до действия); заземлённые ожидания («стажёр, который быстро учится»); каждое касание даёт видимую ценность за 5 секунд; обратимость по умолчанию (видимый undo).

**Три ключевых флоу:**
1. Диалоговый онбординг (8 шагов, ~5 мин): вопросы про заведение/каналы/топ-вопросы гостей/что нельзя без подтверждения → карточки понимания с возможностью поправить → aha-момент (тестовый диалог голосом заведения) → неделя тестового режима с показом всех ответов владельцу.
2. Approval-инбокс: карточка с гостем/сутью/черновиком/причиной/таймером ожидания и кнопками approve/edit/reject; приоритизация по риску × времени ожидания; anti-fatigue — batch-approve, предложение авто-правила после 3 одинаковых решений, дайджест вместо пушей для некритичного; цель ≤5 карточек/день к неделе 4.
3. Отчёт и таймлайн: кликабельные цифры («7 часов = 43 диалога»), перевод в деньги, обязательные разделы (диалоги, брони, исправления, 1–2 инсайта); без сырой телеметрии/процентов точности.

**Паттерны индустрии:** risk-based tiering, progressive delegation, drafts-механика (Superhuman/Gmail), confidence категориями, undo-окно 30 сек, batch review.

**План валидации до кода:** кликабельный мобильный прототип в Figma, 5 тестов по 30 мин с владельцами кафе. Критерии провала: ≥2/5 бросают онбординг или не понимают роль агента; ≥2 одобряют возврат денег не читая сумму; никто не верит цифре экономии — тогда итерация прототипа за неделю.
