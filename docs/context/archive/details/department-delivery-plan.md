# План поставки по отделам (без Ганта)

План Project Manager + Delivery Manager (12.06.2026) для MVP-1 по отделам: DevOps/безопасность (репозиторий, CI/CD с eval-гейтом FN≤2%, staging/prod, мониторинг — джун при наставничестве фаундера), Разработка и данные (ядро пайплайна, policy engine, 6 сценариев, онбординг, инбокс, отчёт — фаундер, позже фронт-дев), Дизайн (UI-кит, Figma-прототип, 5 юзер-тестов — параллельно ядру, UI-код стартует только после валидации прототипа), Тестирование (минимум силами фаундера на MVP-1), Контент (тексты, гайд администратору), Запуск (выбор пилота, недельный прогон, отчёт с решением go/no-go).

**Критический путь:** кастдев блокирует сценарии и policy-матрицу для ядра и дизайна (черновик нужен к концу недели 1); пайплайн ядра + policy engine + eval лежат целиком на фаундере — день его простоя = день сдвига 1:1, митигация — фронт-дев берёт инбокс/отчёт по готовому API-контракту.

**Майлстоуны MVP-1:** M1 скелет+CI, M2 policy-ядро (один сценарий e2e, обход невозможен), M3 прототип валидирован (≥4/5 юзер-тестов успешны), M4 функциональная полнота (6 сценариев, FN≤2%, p95≤10с), M5 пилот-готовность, M6 пилот жив (7 дней без severity-1, ≥20 диалогов, отчёт с go/no-go).

**Definition of Done** прописан на трёх уровнях (задача/эпик/этап) — от зелёных тестов и пройденного eval-гейта до принятого отчёта пилота и приоритизированного бэклога следующего этапа.

**Риски поставки:** тихое затухание фаундера (митигация — вестинг-клифф и правило эскалации по срокам), фаундер как узкое место (API-контракты заранее), уход дизайнера (Figma в командном тиме), джун-девопс тонет (шаблоны, парные сессии), кастдев не даёт сценарии (фаундер фиксирует черновые сам на неделе 1), скоуп-расползание (фриз после M2).

**Коммуникация:** одна доска, еженедельный созвон 30 мин, асинхронные статусы 2 раза в неделю, немедленная эскалация фаундеру при: действии мимо policy-слоя, красном eval в main, инциденте на пилоте, риске выпадения на неделю+, утечке секретов.
