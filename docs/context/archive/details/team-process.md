# Процесс команды (part-time, доли, без карго-культа)

Рекомендации Scrum Master / Agile Coach (12.06.2026) для part-time команды с долями.

**Ритм:** канбан вместо спринтов (спринты с обязательствами не работают при плавающей ёмкости part-time — провал деморализует и маскирует затухание участника). Доска GitHub Projects (Backlog → Ready → In Progress → Review → Done), жёсткий WIP-лимит — 1 активная задача на человека. Воскресный demo-day даёт ритм и дедлайн без давления спринта.

**Асинхронные ритуалы:** короткий чекин во вторник и пятницу (сделал/дальше/блокер/доступность), блокеры сообщаются немедленно, а не ждут чекина. Demo-day каждое воскресенье — видео/скрин/ссылка, признание «пустой недели» вслух — главный механизм против скрытого затухания. Раз в месяц — живой созвон-ретро 45 мин, единственный обязательный.

**Оценка времени фаундера:** оценка задач только «к какому demo закрою», задача больше двух demo — режется. Фаундер выделяет один «офисный час» в неделю на ревью и вопросы; приёмку максимально делегируют (дизайнер принимает UI, продажник — формулировки, фаундер — только код ядра).

**Борьба с затуханием:** публичное обязательство при взятии задачи; правило красной недели (пропущенный чекин+demo без предупреждения → задача автоматически возвращается в Ready, две красные подряд → разговор о паузе вестинга); вестинг привязан к активному вкладу (минимум 2 принятых задачи в месяц), а не к календарю — клифф как фильтр известен всем с первого дня.

**Сигналы здоровья процесса:** lead time ≤14 дней, задач без движения 7+ дней — ноль (тревога при ≥2), review ≤3 дней, demo-day покрытие ≥4/5, поток ≥3 задач/нед.

**Анти-паттерны, которых явно избегают:** ежедневные стендапы, оценки в часах, velocity/burndown, еженедельные ретро, фаундер-диспетчер, Jira (до 10 человек хватает GitHub Projects + Telegram).
