# Архитектурное видение фаундера: мастер-агент и память

Ориентир — Hermes/OpenClaw, но без их абстракций. Ключевые принципы: (1) мастер-агент — единый «менеджер», к которому обращается пользователь и который маршрутизирует задачи саб-агентам (для общепита мастер-агент = «администратор» заведения), но обращение напрямую к функции тоже возможно; (2) память — продуктовое ядро, не фича: агент сам пополняет md-файлы о бизнесе/человеке, это делает его уникальным и растущим, а не статичным промптом; (3) инструменты подключаются через MCP + скиллы, а не зашитые интеграции; (4) минимальная зацепленность модулей (каналы/память/политики/инструменты/первая линия слабосвязаны — задел на сборку шаблонов агентов вплоть до «команды разработки»); (5) B2C-трек личной продуктивности (календарь, туду, Obsidian через Git) — фаундер тестирует на себе.

**Скоупинг MVP:** память как md-файлы (identity/knowledge/policies/learned) — в MVP. Мастер-агент в MVP — единственный агент, маршрутизация к саб-агентам — архитектурный задел (P2). Внутренний контракт инструментов MCP-совместим с первого дня, внешние MCP-серверы — P1/P2. Политики и сценарии как md-скиллы — в MVP. B2C-трек (Obsidian/календарь/туду) и шаблоны команд агентов — P2/P3.

**Требуемая модульная декомпозиция ядра:** Channel Adapter, Front Line (детерминированные ответы), Memory (md-хранилище: identity.md, knowledge/, policies/, learned/), RAG, Risk/Policy Engine, Approval Service, Tool Registry (MCP-совместимый), Reporter, Master Router (в MVP — passthrough). Модули общаются через типизированные события.
