# Роль: DevOps / SRE / Security (архив)

Часть ролевого синтеза команды. Основной тезис: обещания продукта читаются как security-стек компании серии B, а команда — 1-2 человека, поэтому нужна честная сортировка.

Реально и критично (делать самим — это и есть продукт): Policy Gateway с default deny, scoped credentials через secrets broker, audit log каждого tool call, approvals, emergency freeze. Реально через managed-сервисы: sandbox (hosted agents с sandbox, либо Firecracker/gVisor через E2B/Modal), tenant-изоляция через namespace в vector DB + RLS в Postgres, шифрование через KMS. Маркетинг нужно честно сузить: «redaction PII» на минимальном бюджете — это regex+Presidio, не enterprise DLP; «отдельные ключи шифрования» — envelope encryption per-tenant через KMS, не HSM; «Trust Center» — пока страница документации. Главное противоречие идеи: «network allowlist» реален только если весь egress агентов идёт через свой прокси — если runtime-agnostic адаптеры ходят в сеть сами, allowlist фиктивен. Опасная иллюзия: prompt injection не «решается», а только ограничивается blast radius — так и говорить клиентам.

Минимальная инфраструктура MVP (~$300-700/мес): один облачный провайдер (AWS ECS Fargate или Fly.io), RDS Postgres с RLS per-tenant, без Kubernetes; секреты через AWS Secrets Manager + STS для короткоживущих кредов (агент никогда не видит сырой секрет); sandbox — не строить своё, использовать E2B/Modal/Browserbase; весь трафик агентов через forward proxy (Smokescreen/Envoy) — закрывает SSRF и allowlist одним механизмом; audit log — append-only + hash-chain, экспорт в S3 Object Lock; identity — агент как service principal с owner-человеком и kill switch, WorkOS/Auth0 для людей. OWASP ASI дёшево закрывается: default deny + scoped tokens (tool misuse/privilege abuse), managed sandbox (code execution), подпись/provenance записей памяти (memory poisoning), подписанные skill-манифесты (supply chain), rate limits + budget caps (cascading failures), kill switch + TTL сессий (rogue agents); goal hijacking — только смягчение через spotlighting источников + approvals.

Риски: cross-tenant утечка через баг в RLS/namespace — самый страшный сценарий, способный убить компанию; утечка секрета через логи/трейсы LLM; обход approval через переформулировку действия; логи промптов сами по себе содержат PII клиентов. Стоимость sandbox-минут и egress-прокси растёт линейно с usage — при 20 активных клиентах инфра уйдёт к $2-5k/мес. Compliance: SMB спросит SOC 2 уже на пилоте — Type I реально к концу года через Vanta/Drata (~$10-15k+аудит), Type II нет, HIPAA/PCI не обещать. Не обещать: защиту от prompt injection (только containment), SLA на freeze <N секунд, BYOK/HSM, on-prem, готовый пентест-отчёт. On-call из одного человека = честный SLA 99.5%, не 99.99%.

План: этап 1 (2-3 недели) — инфра для Security PoC, Terraform с первого дня, стенд с гейтвеем + 2 фейковых тенанта + sandbox + прокси; Security PoC по 7 пунктам (prompt injection, malicious skill, shell abuse, SSRF, кража secret, cross-tenant, approval bypass) — каждый как записанное демо для design partners. Этап 2 (1-2 мес) — CI/CD (Semgrep, Dependabot, gitleaks, tfsec), staging+prod, миграции только через CI. Мониторинг — Grafana Cloud free tier + Sentry, алерты на всплеск denied actions/аномальный egress/fail audit; freeze-кнопка тестируется еженедельно. Этап 3 — Vanta с первого клиента, security-страница, инцидент-процесс на бумаге, табличный отчёт PoC как sales-артефакт.

Запросы к другим ролям: от бизнеса — бюджетный потолок инфры и решение по SOC 2 Type I сейчас; от sales — не продавать HIPAA/on-prem/BYOK, security-анкеты присылать до подписания; от маркетинга — формулировки «containment, not prevention»; от технарей — весь egress через прокси без исключений; от поддержки — runbook эскалации security-инцидента.
