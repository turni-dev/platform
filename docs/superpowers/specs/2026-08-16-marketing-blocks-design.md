# Маркетинг-слой блоков и CMS-билдер страниц

**Дата:** 16.08.2026
**Карта:** С1 [E6] Маркетинг-слой компонентов для лендинга (разбита на три карты, см. «Слайсы»)
**Заметки:** `Агентский трек — бизнес-процесс и видение` (структура L1–L7), `НФТ и фронт-архитектура`

## Зачем

Лендинг сейчас — одна страница с заголовком и кнопкой. Нужно, чтобы владелец собирал
страницу в админке Strapi из готовых блоков, а не звал разработчика на каждую правку
секции. Значит нужен слой маркетинговых блоков в `apps/core-site` и контент-модель в
`apps/cms`, где один блок кода соответствует одному компоненту Strapi.

## Границы

Маркетинг-трек и продукт не пересекаются. `core-site` ходит в Strapi напрямую по
`CMS_BASE_URL` — ровно так, как уже описано в `compose.marketing.yml`. Продуктовый
бэкенд про CMS не знает: `StrapiCmsAdapter` в `platform/integrations/strapi` не подключён
ни к одной композиции и таким и остаётся. Публичный сайт обязан жить, когда продуктовый
стек лежит, и наоборот.

`packages/ui` не меняется. Tailwind остаётся внутри кита; маркетинг-слой — SCSS-модули
поверх тех же CSS-переменных `--turni-*`. Контракты и миграции продукта не трогаем, поэтому
founder review не требуется.

```
apps/core-site/src/marketing/
  blocks/<name>/{schema.ts, <name>.tsx, <name>.module.scss}
  page-schema.ts        дискриминированный union по __component
  block-renderer.tsx    карта __component → компонент
  content/cms-page-source.ts   fetch Strapi → Zod → fallback
  content/seed/home.json       семя L1 в репозитории
  styles/marketing.scss        контент-колонка, брейкпоинты, ритм
apps/core-site/src/app/api/leads/route.ts
apps/cms/src/components/marketing/*.json
apps/cms/src/api/{page,lead}/
```

## Блоки

Девять блоков закрывают все секции L1 (S1–S10). Имя в Strapi — `marketing.<kebab>`,
оно же дискриминант `__component` в схеме.

| `__component` | Компонент | Секции | Поля |
| --- | --- | --- | --- |
| `marketing.nav` | `Nav` | S1 | `brand`, `links[]{label,href}`, `cta?{label,href}` |
| `marketing.hero` | `Hero` | S1 | `heading`, `subheading`, `primaryCta{label,href}`, `secondaryCta?{label,href}`, `media?{src,alt,width,height}` |
| `marketing.feature-grid` | `FeatureGrid` | S2, S4, S7 | `heading?`, `columns?` (2\|3), `items[]{title,body?}` |
| `marketing.steps` | `Steps` | S3 | `heading`, `steps[]{title,body}`, `note?` |
| `marketing.security-list` | `SecurityList` | S5 | `heading`, `items[]{title,body?,icon?}` |
| `marketing.case-cards` | `CaseCards` | S6 | `heading`, `emptyState?{body,cta{label,href}}`, `cases[]{title,task,built,result,href?}` |
| `marketing.faq` | `FaqAccordion` | S8 | `heading`, `items[]{question,answer}` |
| `marketing.lead-form` | `LeadForm` | S9, L2 | `heading`, `note?`, `submitLabel`, `consent{label,href}` |
| `marketing.footer` | `Footer` | S10 | `contacts[]{label,href?}`, `legalLinks[]{label,href}`, `note?` |

Ни одной строки копирайта в коде: весь контент приходит пропсами. Карта копирайта
остаётся отдельной и ничего здесь не блокирует — в семени лежат нейтральные заглушки,
которые контентщик заменит в Strapi.

`Nav` и `Footer` — тоже блоки динамической зоны, а не хардкод в `layout.tsx`. Иначе
«билдер» собирает не всю страницу, и обещание из заметки — «на корп-сайте те же блоки
пересобираются в другом порядке» — не выполняется.

`icon` у `SecurityList` — закрытый enum (`shield`, `server`, `eye`, `audit`), SVG
инлайновые. Свободная строка означала бы иконочный шрифт или зависимость; ни того, ни
другого при гейте Lighthouse ≥90 не хотим.

### Zod как источник правды

Схема блока на Zod валидирует ответ CMS **и** проверяет, что JSON-схема Strapi не разъехалась
с кодом: отдельный тест сравнивает набор полей `apps/cms/src/components/marketing/*.json`
с соответствующей Zod-схемой. Без такого теста расхождение обнаруживается только в проде
пустой секцией.

## Рендеринг и отказы

`page.tsx` → `cms-page-source` → Zod → `block-renderer`.

Источник контента возвращает семя из репозитория, когда: `CMS_BASE_URL` не задан, Strapi
недоступен или ответил не 2xx, страница со слагом не заведена, ответ не прошёл валидацию.
Каждый такой случай пишет предупреждение (без тела ответа) и отдаёт семя. Сайт не падает
никогда, а локальная разработка и тесты не требуют поднятого Strapi.

Слаг без семени и без записи в CMS — обычный 404 Next.js.

Неизвестный `__component` рендерер пропускает молча: в Strapi блок может появиться раньше,
чем задеплоен фронт, и одна незнакомая секция не должна ронять страницу.

## Приём лидов

Браузер шлёт на свой же origin `POST /api/leads`; route handler валидирует Zod, проверяет
honeypot и обязательное согласие ПДн (152-ФЗ), затем пишет в Strapi серверным токеном.
Публичного `create` у коллекции `lead` нет, токен записи в браузер не попадает.

Идемпотентность — по `Idempotency-Key`, который форма генерирует один раз на попытку:
повторная отправка того же ключа не создаёт вторую заявку.

Тело заявки не логируется — только факт приёма и идентификатор. Хранимые поля: имя,
контакт, компания, задача, каналы, наличие сервера, срок, факт и время согласия. Ничего
сверх этого не собираем.

Форма работает без JS: обычный `method="post" action="/api/leads"`. JS добавляет состояния
ошибки, спиннер и защиту от повторного клика.

## Тесты

Vitest + `renderToStaticMarkup`; jsdom и testing-library не заводим — весь слой, кроме
состояний формы, серверный.

- разметка каждого блока: заголовки, ссылки, `label`/`for`, `details/summary` у FAQ;
- рендерер пропускает неизвестный `__component` и сохраняет порядок блоков;
- семя проходит схему страницы;
- паритет полей Zod ↔ JSON-схем Strapi;
- источник контента на fake fetch: успех, 500, мусор в теле, отсутствующий слаг;
- route handler на `Request` + fake fetch: валидный лид, отсутствующее согласие, honeypot,
  повтор по идемпотентному ключу, недоступный Strapi.

## Адаптивность и производительность

Контент-колонка ≤1120px, текст ≤720px, тач-цели ≥44px, body ≥16px. Брейкпоинты
≥1280 / 768–1279 / <768, desktop 2–3 колонки → mobile одна. Клиентского JS в блоках нет
нигде, кроме LeadForm. Шрифты — системный стек, как сейчас. Tailwind-рантайм за пределы
`packages/ui` не выходит.

## Слайсы

1. **С1 [E6] Маркетинг-слой компонентов** — схемы, девять блоков, SCSS-модули, рендерер,
   семя, главная из семени. Сеть не задействована.
2. **С1 [E6] CMS-билдер страниц** — компоненты и content-type `page` с динамической зоной
   в Strapi, чтение из core-site с fallback, тест паритета схем.
3. **С1 [M1 Growth] Приём лидов** — коллекция `lead`, route handler, состояния формы.

Одна ветка `feat/marketing-blocks`, коммит на слайс.

## Что сюда не входит

- Копирайт лендинга — отдельная карта, блокирует только вёрстку финальных текстов.
- Страницы L4 (юридические), L5 (кейсы), L6 (блог) — шаблоны появятся, когда появится
  контент; блоки под них уже переиспользуемы.
- Живое демо виджета в Hero — пока статичное изображение, как решено в заметке.
- Превью черновиков и локализация Strapi — YAGNI до первого реального редактора.
