# UI-кит на Ant Design — карточка для агента

> **Статус: не начато, только спецификация.** Этот документ описывает, что нужно сделать, чтобы `packages/ui` и `apps/web` перешли с текущего голого SCSS (без компонентной библиотеки) на Ant Design. Живой референс — опубликованный канвас Claude Design: https://claude.ai/code/artifact/16341284-d850-43e9-b177-779eb68b0396 (2 страницы: «Основы и UI-кит», «Кабинет (apps/web)»). Исходники артбордов (`.dc.html`, не код продукта — только визуальный референс) лежат рядом в `docs/design/canvas/` для переоткрытия канваса при необходимости правок макета.

## Решение (22.08.2026)

Заменяет `docs/design/design-ux.md` §4.7, где было записано «shadcn/ui + Radix». Решение владельца: UI-кит — **Ant Design**. Причина смены не в коде — на момент решения `packages/ui` не содержал ни shadcn, ни Ant, только 4 файла (`index.ts`, `provider.tsx`, `theme.ts`, `tokens.scss`) без единого компонента; `apps/web` рисует интерфейс голым SCSS без библиотеки вообще (см. `apps/web/src/app/(cabinet)/cabinet.module.scss` — инлайновые хардкод-цвета, ни одного переиспользуемого компонента). Так что это не миграция реального компонентного кода, а выбор библиотеки для кода, которого ещё не существует.

## Что нужно сделать (объём карточки)

1. **Установить и подключить Ant Design** в `packages/ui` (зависимость `antd`) и прокинуть тему через `ConfigProvider` в `provider.tsx` (сейчас там что-то другое/пусто — проверить перед правкой).
2. **Смаппить токены** `packages/ui/src/tokens.scss` на Ant `theme.token` (см. таблицу ниже) — не удалять существующие `--turni-*` CSS-переменные, если их читает виджет (`packages/widget`) или `apps/core-site`; только `apps/web` переходит на Ant целиком.
3. **Собрать реальные компоненты** в `apps/web`, заменив голый SCSS в `(cabinet)/*`: `Button`, `Card`, `Tag`, `Switch`, `Avatar`, `Statistic`, `Alert` — по образцу страницы «UI-кит» канваса.
4. **Реализовать экраны кабинета**, для которых сейчас нет UI вообще (см. `docs/context/frontend-backend-parity.md` — это тот самый разрыв бэкенд/фронтенд):
   - Дашборд (сейчас `(cabinet)/dashboard/page.tsx` — пустая заглушка, строки 27-30) → см. канвас «Дашборд (D1)».
   - Approval-инбокс + карточка решения (сейчас нет вообще, backend API уже есть: `GET /api/v1/automations/pending`, `POST /api/v1/automations/:id/approve`, `POST /api/v1/automations/:id/reject`) → канвас «Решения — список (A1)» и «Решение — карточка (A2)».
   - Подключения Google/VK (сейчас нет вообще, backend API уже есть: `/api/v1/integrations/google*`, `/api/v1/channels/vk`) → канвас «Подключения».
   - Автоматизации (сейчас `(cabinet)/agent/automations/page.tsx` содержит устаревший текст «появится, когда карты приземлятся» — они уже приземлились) → канвас «Автоматизации».
5. Виджет G1 (`packages/widget`) **не трогать** — отдельная сборка без Ant, только подмножество токенов, бюджет ≤70KB (см. `design-ux.md` §4.7).

## Маппинг токенов (Ant `theme.token`)

Источник — страница «Основы» канваса. Значения ниже — то, что реально нарисовано на макетах; сверить с актуальным `packages/ui/src/tokens.scss` перед реализацией (файл мог измениться после публикации этого документа).

```ts
// packages/ui/src/theme.ts — ориентир, не готовый код
const theme = {
  token: {
    colorPrimary: '#176b4d',       // --turni-accent, бренд Turni поверх дефолтной Ant-палитры
    borderRadius: 6,               // Ant default
    borderRadiusLG: 8,
    fontFamily: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`
    // colorSuccess/colorWarning/colorError — оставить дефолты Ant (#52c41a/#faad14/#ff4d4f),
    // бренд только в primary — так решено на канвасе, не переопределять весь набор.
  }
};
```

Дополнительный некатегоричный цвет с канваса — `--owner` (`#722ed1`, фиолетовый) для реплик владельца в диалоге (в отличие от гостя/агента) — это Ant `purple` из стандартной палитры, не новый токен.

## Ловушки

- Не путать это с виджетом (`packages/widget`) — у него свой бюджет и своя (не-Ant) сборка.
- `apps/core-site` (корп-сайт) в этот объём **не входит** — там своя лента задач, Ant Design не обсуждался для сайта.
- Мобильные touch-таргеты: Ant-контролы по умолчанию 32px — на макетах CTA увеличены до 44–48px поверх стандартной высоты (см. канвас «Основы» → «Радиусы и высоты контролов»). Не оставлять 32px для основных действий владельца с телефона.
- Approval-карточка не даёт свайпом одобрять решения с деньгами/риском (см. канвас «Решения — список» — вторая карточка размечена как «только через карточку решения»); это уже было решено в продуктовой спеке (`docs/design/design-ux.md` §2, карта A1) — сохранить при реализации.
- Перед реализацией — открыть канвас и свериться визуально; этот документ описывает решения и ловушки, но не заменяет сам макет.
