## 1. Роли сторон

- **Оператор** — **[ПЛЕЙСХОЛДЕР: наименование Исполнителя/Оператора после регистрации ИП/ООО]**, определяет цели и средства обработки персональных данных владельцев и их контрагентов в связи с оказанием услуг персональных автоматизаций.

## 2. Yandex AI Studio — RU-LLM/embeddings-субобработчик

### 2.1. Роль в архитектуре
В соответствии с `docs/context/architecture/llm-runtime.md` (RU-first LLM-рантайм) Yandex AI Studio является основным (primary) провайдером для:
- генерации ответов и черновиков (`generate`);
- классификации/оценки риска (`classify`);
- построения векторных представлений для RAG (`embed`, Yandex Text Embeddings v2, 768-мерные вектора);
- оценки качества (`judge`) в CI-пайплайне (офлайн, вне контура пользовательских данных в проде).

Доступ реализован за портом `LlmPort`/`EmbeddingPort` — вендорские детали не протекают в домен продукта (закон границы портов), что облегчает будущую замену или добавление второго провайдера без пересмотра прикладного кода.

### 2.2. Категории обрабатываемых данных
- текст запросов/сообщений пользователей и владельцев, прошедший redaction (замена ФИО/телефона/email на плейсхолдеры вида `[PERSON_1]`, `[PHONE_1]` и т. п.) перед отправкой — redaction обязательна и работает по принципу fail-closed (при невозможности редактирования запрос не отправляется);
- фрагменты базы знаний/контекста, используемые для формирования ответа (RAG);
- служебные метаданные запроса, необходимые для маршрутизации и учёта стоимости (роль модели, токены, latency), без прямой идентификации субъекта.

### 2.3. Локализация и трансграничная передача
Yandex AI Studio эксплуатируется в контуре Yandex Cloud на территории Российской Федерации. Согласно `docs/context/architecture/llm-runtime.md` (раздел «Безопасность / 152-ФЗ») использование Yandex AI Studio как primary-провайдера снимает основную часть риска трансграничной передачи, характерного для иностранных LLM-провайдеров (ранее — OpenRouter). Второй (потенциально иностранный) LLM-провайдер в MVP отключён; при его включении в будущем передача персональных данных туда без redaction запрещена политикой продукта, а для тенантов с флагом «только RU» такой маршрут полностью недоступен.

### 2.4. Цель и основание привлечения
Обработка данных через Yandex AI Studio производится исключительно для оказания услуги (генерация ответов Агента, классификация риска, построение эмбеддингов для поиска по базе знаний Владельца) — то есть в рамках исполнения договора с Заказчиком/Владельцем (см. `docs/legal/privacy-policy.md`, раздел 5).

### 2.5. Условия обработки (DPA) — статус
**[ПЛЕЙСХОЛДЕР — требует юридической проработки и, при необходимости, отдельного договора/приложения с Yandex Cloud/Yandex AI Studio:]**
- проверить, покрывает ли типовой договор оферты Yandex Cloud/Yandex AI Studio обязательства обработчика персональных данных в объёме, достаточном для целей Оператора (конфиденциальность, недопустимость использования данных клиента для дообучения общих моделей, сроки хранения на стороне провайдера, порядок уведомления об инцидентах);
- зафиксировать, не обучается ли модель Yandex AI Studio на данных, переданных через API Оператора (принцип продукта — не обучать модель на данных клиента, см. `docs/context/security-and-quality.md`);
- зафиксировать регламент и SLA реагирования на инциденты безопасности со стороны Yandex Cloud;
- определить, требуется ли отдельное юридически значимое соглашение (DPA/приложение к договору) или используются стандартные условия обработки данных облачного провайдера — решить с юристом.

### 2.6. Меры защиты на стороне Оператора
Помимо условий у провайдера, Оператор применяет собственные меры снижения риска до передачи данных в Yandex AI Studio: redaction PII перед LLM (fail-closed), запрет логирования тела сообщений и секретов, изоляция тенантов на уровне доступа к данным (RLS/`withTenant`), фильтрация embedding-поиска по `embedding_model` и tenant-контексту (см. `docs/context/security-and-quality.md`, LLM02/LLM08 в кросслисте OWASP LLM Top 10).

| Субобработчик | Роль | Данные | Локализация | Статус |

## 4. Общие принципы работы с субобработчиками

- субобработчик привлекается только для целей, совместимых с целями обработки, заявленными в `docs/legal/privacy-policy.md`;
- к субобработчику предъявляются требования по обеспечению конфиденциальности и безопасности не ниже уровня, применяемого Оператором;
- смена или добавление субобработчика, обрабатывающего персональные данные уровня 3 (см. классификацию в `docs/legal/privacy-policy.md`, раздел 3), должно сопровождаться обновлением настоящего документа и, при необходимости, раздела 7.2 Политики обработки персональных данных до начала обработки.
